# Adversarial review — 2026-11-08

Scope: the whole repository at `7cb2e1a` (code, tests, skill, README), judged against the goal
"an AI agent, possibly a weak one, uses this in an auto shop on the Hondas or the Hyundai to diagnose
problems and reset errors". Sources of findings: my own full read (prefix **C**), the open items from
the three review rounds on `2bbc0d6` (prefix **R**), an independent protocol-layer reviewer (**P**),
and an independent data/clear/skill reviewer (**D**). Every finding has a concrete failure scenario;
anything without one was discarded.

Status column: `fixed <commit>` · `wontfix: <reason>` · `open: <why>`.

## Findings

| id | sev | area | problem → failure scenario | status |
|---|---|---|---|---|
| C1 | high | elm | ISO-TP consecutive frames are not sequence-checked and a short reassembly is still emitted: one dropped frame (`<RX ERROR` line skipped) shifts every later byte, so Kona 220101–220105 decode wrong cell voltages, SOH and temperatures, and can raise a false Critical cell-imbalance finding that is then saved to history | fixed (phase 1) |
| C2 | high | serial | After a read timeout the adapter is left mid-command; the next write interrupts it, the next reply starts with `STOPPED`, and that command fails too — one slow request cascades into a failed scan | fixed (phase 1) |
| C3 | high | adapter | `LV RESET` (adapter rebooted, e.g. cranking voltage dip) is only reported as an error; the adapter has silently gone back to echo on / headers off, so every later reply is misparsed (K-line: the 3rd data byte is taken as the ECU address) | fixed (phase 1) |
| C4 | medium | adapter | Init commands are never checked for `OK`; on an adapter that rejects one (`?`), e.g. `ATH1` on a clone, every later reply is parsed with the wrong framing and produces garbage instead of an error | fixed (phase 1) |
| C5 | medium | serial | `open()` drains stale output with no deadline; an adapter left streaming (monitor mode from a crashed session) makes `carlink` hang forever before it sends anything | fixed (phase 1) |
| C6 | medium | serial | Auto-detect falls back to any `usbserial` device and sends it `ATZ` without checking it is an ELM/STN adapter; in a shop with other USB-serial equipment the wrong device gets commands | fixed (phase 1) |
| C7 | medium | serial | A port already open by another `carlink` process fails with a raw OS/flock error the agent cannot act on | fixed (phase 1) |
| C8 | high | report | History is keyed by vehicle profile, so in a shop every 2016 Odyssey that comes in shares one history — trends and "code first seen" mix different customers' cars | fixed (phase 1) |
| C9 | medium | report | `--vehicle` and a VIN that identifies a different car are not compared; the wrong profile's notes and resets are applied silently | fixed (phase 1) |
| C10 | medium | cli | Errors are `{"error": "<text>"}` with no machine-readable kind or remediation, and clap usage errors are plain text on stderr — a weak agent that mistypes a command gets no JSON and no next step | fixed (phase 1) |
| C11 | medium | cli | JSON keys are emitted alphabetically, so a scan prints ~100 cell voltages before `summary` and `findings`; an agent with a small context window reads the noise and misses the conclusion | fixed (phase 1) |
